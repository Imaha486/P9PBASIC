# 近似・特例の棚卸し（2026-11-19）

P8PBASIC の実装にある近似・部分実装・環境依存を全て洗い出し、
処遇を決めた記録。処遇は3種:

- **G（一般化）**: ハードウェア／仕様として正しく実装し直す。次期作業。
- **D（文書化した近似）**: 根拠を明記した上で近似のまま維持する。
  黙って置かないことが目的で、壊れたらここを見て判断する。
- **V（検証不足）**: 実装は実コード中継などで正しいはずだが、
  検証が届いていない。検証スイート側の課題。

## G: 一般化する

1. **ホストCLIにディスク実体化が無い**（src/main.c / src/fileio.c）
   埋め込みエンジン（src/engine.c の materialize）は p88disk.c で
   D88 のファイルを scratch へ実体化してからインタプリタを回すが、
   ホストCLIにはその段が無く、BLOAD/RUN はカレントディレクトリの
   実ファイルしか読めない。開発中は抽出済み NEOMSC が作業フォルダに
   置いてあったため表面化しなかった（2026-11-19、検証スイート構築
   時に発覚。素のフォルダでは全プローブが10行目でファイル無し
   エラーになる）。一般化: ホストCLIにも materialize を共有させ、
   `P8P_DISK` 指定時はディスクから直接起動できるようにする。
   スイートは当面 p88_extract.py で NEOMSC を抽出して回避している。

2. **ディスクサブシステムの書き込みコマンドがデータを捨てる**
   （src/vessel.c、cmd 0x01: "write: data discarded"）
   読み取り系（00/02/03/06/07/12/17/18/23）は D88 バックで再現済み
   だが、書き込みは成功を返して何もしない。NEOMSC は書き込みを
   使わないため MA2026 では無害。一般化: D88 への書き戻し
   （イメージが書き込み可能な場合のみ）を実装する。

3. **ポート 0x31 bit1（64RAM ウィンドウ）が未モデル**
   （src/vessel.c はポート値を保持するだけ）
   bit1 を立てると 0x8000–0x83FF が RAM ウィンドウになる。
   NEOMSC は CG 展開と OPNA バーストの前後でトグルするが、RD=1
   構成の MA2026 では実害が無いことを実測で確認済み。一般化:
   Z80 バス側にウィンドウをモデル化する（VRAM ウィンドウと同型）。

4. **ゲストテキストイメージ（0xF3C8）の表示合成**【2026-11-19 解決】
   実機では 0xF3C8 はテキスト VRAM そのものだが、埋め込み
   エンジンはインタプリタ自身の画面（halp8 の tv/ta）とゲスト
   イメージの二面持ちだったため、イメージだけに描くものが
   アプリで見えなかった: FFDE サービス3のスタッフロ―ル全文と、
   BASIC 本体が TXR=&HF418（イメージの属性面）へ POKE する
   選択カーソル／再生中マーカーの属性。
   解決: src/engine.c の p8_text_codes / p8_text_attrs が二面を
   合成して返す（p8_frame のグラフィック合成と同じ方針）。
   イメージのコードが勝ち（空白 0x20 は素通し、漢字は SJIS
   ペア→インタプリタの JIS パック形式へ変換）、属性は CRTC
   トランスペアレント形式の（桁，属性）ペア列を QUASI88 の
   crtcdmac と同じ意味論でデコードする: 色コマンド（bit3）は
   色＋セミグラフィックを指定し装飾を保持、装飾コマンドは
   色とセミグラフィックを保持する（カラー属性モード）。
   属性ペアはインタプリタのセルも再色付けする（ただしセルの
   色を実際に変える場合のみ。リストの緑／シアンの列と
   マーカーがこれで効く）。検証: tools/textmerge_test.c
   （単体 18 件）とスイートの embed text 段（*SELECT 画面）。
   残る既知の差: (a) インタプリタの CLS はゲストイメージを
   消さないため、属性ペアを再構築しない行では古いイメージが
   勝ち得る（MA2026 は画面ごとにペアを再構築するので無事）。
   (b) セミグラフィックのドット描画はホスト側の仕事: エンジンは
   セルと属性 bit4（グラフィック）を渡すが、RetroDOS の
   P8Bridge はまだ文字グリフで描く。(c) 点滅は位相を持たず
   常時表示、反転は属性バイトに載せていない。

5. **DOS ビルド（build.sh / build.bat）がリンクできない**
   src/fileio.c が vessel_notify_load / vessel_init / vessel_exec を
   呼ぶが、DOS 側のソース一覧に器が無い。P9PBASIC 由来のターゲット
   で、P8 の現行ターゲットはホスト／埋め込み。一般化の方向は
   2択: 器（z80.c + vessel.c は移植性のある C）を DOS にも載せるか、
   DOS ではフックを #ifdef で外して「器なし」を明示する。
   決めるまで壊れたままにしないこと（本書がその記録）。

## D: 文書化した近似（維持）

6. **文単位ポンプ**（src/vessel.c PUMP_SLICE = 16,667 サイクル）
   BASIC の1文ごとに固定量のエミュレーション時間を進める。
   実機では文の実行時間は内容で変わるため、これは時間の近似。
   根拠: MA2026 の体験（ロード中の BGM、割り込み駆動の演奏）は
   この粒度で実機と一致することを QUASI88 差分テストで確認済み。
   サイクル精度の解釈実行は目標にしない（DESIGN の範囲外）。

7. **hal_poll のペーシング**（src/halp8.c、64文ごと）
   埋め込みHALが音声リードを見て眠る間隔。2秒リングが約0.27秒分の
   ポンプを吸収する前提で、コード内コメントに根拠あり。ホストHAL
   では無効（オフライン最速）。近似ではなくホスト側の実行制御。

8. **XDE 転送時間**（src/vessel.c XDE_SECTOR_CYCLES = 133,333）
   約30セクタ/秒。QUASI88 の実測（約35ms/セクタ）で校正した値。
   実機のシーク時間まではモデル化しない。

9. **SOUND 文はビーパー近似**（src/exec.c、P9PBASIC 由来）
   MA2026 は使わない。PC-88 の SOUND は音源ボード前提で、
   器の OPNA へ写すのが正道だが、需要が実証されるまで近似で維持。

10. **ADPCM-A 固定リズムROMは分離点のみ**（docs/DESIGN.md §音楽再生）
   MA2026 同梱 PMD はサンプルRAM駆動で固定レイアウトを使わない
   ことを実測済み。他タイトルで必要になったら供給部を実装する。

11. **VRTC ハンドラのチェーン先 0xE808 は EI;RET スタブ**
    実機では BASIC ROM のハンドラへチェーンする。器には ROM が
    無いためスタブで受ける。PMD のフェード／効果音処理は器側で
    完結しており、MA2026 の挙動に差は出ていない（実測）。

## V: 検証不足（実装ではなく検証の課題）

12. **FFDE サービス2/3**（src/exec.c）: 実ハンドラへ中継しており
    実装は本物。2026-11-19 に検証して以下が確定した。
    - サービス2は「到達不能」ではなかった。menu の *PLAY は
      (0xFFFC)=&HB1（YM2203系）の時だけサービス0で読み、SB2
      構成（&HB2）では全曲がサービス2（XDE 2, packed, PL, &H5500）
      でロードされる。つまり出荷構成の通常経路であり、使用実績
      として検証済みだった。旧記録（RD=1 で到達不能）は誤り。
    - サービス3（スタッフロ―ル）は menu 2990行「Roll」が発動
      （最終曲の終了／キー割り込み）。ハンドラ（0xA83B）は
      サブ機能 8=スクロール、9=作業ポインタ登録、10=テキスト
      イメージ消去、11=モード登録、0–7=色＋文字列描画。
      描画先はグラフィック面ではなく**ゲストテキストイメージ
      （0xF3C8）だけ**で、文字列は 0xCA00 のフォントで
      ドットマトリクス化されセミグラフィックコードとして
      描かれる。当初は描画パスの使う ROM 文字列評価器
      （0x11D3）が未代行で、古い数値記述子の指す先を描く
      本文無関係の固定パターン（1728 バイト）になっていた。
      評価器をトラップで代行してからは本文依存の描画
      （プローブの固定データで 384 バイト、別本文では 348）
      を対照実験で確認した（tests/probes/PROBE53.BAS、
      Tier A で回帰固定）。
    - 表示側も上の一般化 4 の合成で解決済み（2026-11-19）。
      アプリ側のセミグラフィック・ドット描画はホストの残作業。

13. **言語仕様の「推定」2件**（docs/TOKEN-FORMAT.md）:
    FF82 RIGHT$ と FF85 INT。どちらも MA2026 が使い、表示結果が
    実機と一致することまでは確認済みだが、単独の実機照合は無い。
    他タイトル対応の際に QUASI88 で照合する。

14. **PROBE43 の 0x9CBC ポーリング**: PMD 演奏中に XDD 8 を重ねる
    非実機的な構成でのみ起きる器側の観察事項。実機構成では
    発生しないため、エンジンではなくプローブ側の既知事項とする。
