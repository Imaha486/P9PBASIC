# 近似・特例の棚卸し（2026-11-19）

P8PBASIC の実装にある近似・部分実装・環境依存を全て洗い出し、
処遇を決めた記録。処遇は3種:

- **G（一般化）**: ハードウェア／仕様として正しく実装し直す。次期作業。
- **D（文書化した近似）**: 根拠を明記した上で近似のまま維持する。
  黙って置かないことが目的で、壊れたらここを見て判断する。
- **V（検証不足）**: 実装は実コード中継などで正しいはずだが、
  検証が届いていない。検証スイート側の課題。

## G: 一般化する

1. **ホストCLIにディスク実体化が無い**【2026-11-19 解決】
   埋め込みエンジンの実体化を src/materialize.c に切り出して共有
   化した。ホストCLI（build-host.sh が -DP8_HOST_MATERIALIZE で
   ビルドする src/main.c）は `P8P_DISK` 指定時、エンジンと同じ
   scratch へ実体化してから走る: プログラム引数があればその
   ファイルを自ディレクトリから（絶対パスで）読み、ゲストの
   ファイルアクセスは scratch 側で解決する。引数が無ければ
   ディスクのブートプログラム（MENU 優先）が起動する。
   `P8P_DISK` 無しでは従来どおり実ファイルのみで動く。DOS /
   Windows ターゲットはマクロ無しでビルドされ影響を受けない。
   検証: 素のフォルダ＋PROBE2 が Tier A 値で完走、空フォルダから
   の無引数ブートでゲームが起動継続、回帰スイート（抽出回避策を
   撤去済み）全段パス。なお RetroDOS アプリ側ツリーへは次回同期
   時に src/materialize.c の追加が必要。

2. **ディスクサブシステムの書き込みコマンド**【2026-11-19 解決】
   cmd 0x01 のデータ相をバッファし、完了時に読み取りと同じ
   セクタ走査（16 の次は次トラックの 1）で D88 イメージへ
   書き戻す実装にした。書き戻し先はメモリ上のイメージのみで、
   ディスクファイル自体は変更しない（器はファイルを "rb" で
   一括読みして閉じる）。つまり書き込みはセッション内では
   実フロッピー同様に全リーダー（サブシステム／ファイル層／
   XDE サービス）から見えるが、ユーザーの .D88 は守られる。
   検証: tools/subsys_test.c（PUTCOM/PUTDAT 経由の書き込み→
   サブシステム読み戻し＋ファイル層読みの一致、セクタ16→
   次トラックのラップ、ファイル無変更の確認）。NEOMSC は
   書き込みを使わないため MA2026 の動作は従来どおり。

3. **ポート 0x31 bit1（64RAM ウィンドウ）**【2026-11-19 解決】
   0x8000–0x83FF は通常、ポート 0x70 で基底を決める 1KB の
   RAM ウィンドウ（OUT 0x70 = 値<<8、IN 0x70 で読み戻し）で、
   ポート 0x31 の bit1（64K RAM）または bit2（N）が立つと
   恒等マッピングになる（QUASI88 の
   main_memory_mapping_8000_83ff の意味論）。src/vessel.c の
   Z80 バス（mem_read / mem_write）に実装した。基底の初期値は
   0x8000（恒等）で、起動済み BASIC が残す状態に合わせたため、
   ゲストがポート 0x70 / 0x31 を触らない限り従来動作と一致
   する。器自身のサービス（XDE のネイティブ転送等）は DMA
   相当としてフラットアドレスのまま。検証:
   tools/window_test.c（Z80 ルーチン経由の読み書き 11 件）。
   NEOMSC は CG 展開と OPNA バーストの前後でトグルするが、
   RD=1 構成の MA2026 では従来どおり実害なし（回帰スイートで
   再確認）。

4. **ゲストテキストイメージ（0xF3C8）の表示合成**【2026-11-19 解決】
   実機では 0xF3C8 はテキスト VRAM そのものだが、埋め込み
   エンジンはインタプリタ自身の画面（halp8 の tv/ta）とゲスト
   イメージの二面持ちだったため、イメージだけに描くものが
   アプリで見えなかった: FFDE サービス3のスタッフロ―ル全文と、
   BASIC 本体が TXR=&HF418（イメージの属性面）へ POKE する
   選択カーソル／再生中マーカーの属性。
   解決: src/engine.c の p8_text_codes / p8_text_attrs が二面を
   合成して返す（p8_frame のグラフィック合成と同じ方針）。
   イメージのコードが勝ち（空白 0x20 は素通し、漢字は SJIS
   ペア→インタプリタの JIS パック形式へ変換）、属性は CRTC
   トランスペアレント形式の（桁，属性）ペア列を QUASI88 の
   crtcdmac と同じ意味論でデコードする: 色コマンド（bit3）は
   色＋セミグラフィックを指定し装飾を保持、装飾コマンドは
   色とセミグラフィックを保持する（カラー属性モード）。
   属性ペアはインタプリタのセルも再色付けする（ただしセルの
   色を実際に変える場合のみ。リストの緑／シアンの列と
   マーカーがこれで効く）。検証: tools/textmerge_test.c
   （単体 18 件）とスイートの embed text 段（*SELECT 画面）。
   残る既知の差: (a) インタプリタの CLS はゲストイメージを
   消さないため、属性ペアを再構築しない行では古いイメージが
   勝ち得る（MA2026 は画面ごとにペアを再構築するので無事）。
   (b) セミグラフィックのドット描画はホスト側の仕事: エンジンは
   セルと属性 bit4（グラフィック）を渡すが、RetroDOS の
   P8Bridge はまだ文字グリフで描く。(c) 点滅は位相を持たず
   常時表示、反転は属性バイトに載せていない。

5. **DOS ビルド（build.sh / build.bat）**【2026-11-19 決定・対処済】
   P9PBASIC 由来のターゲットで、P9PBASIC.EXE（PC-98 MS-DOS）を
   作るスクリプトがフォークに未適応のまま残っていた。器への
   参照は fileio.c の BLOAD,R だけでなく exec.c 全体（XDE/XDD/
   XDF リレー、文ループの vessel_pump）に及ぶため「フックだけ
   外す」ことはできず、器なしの DOS 版は XDE 系が無言で無効な
   インタプリタになる。16ビットラージモデルに器＋ymfm（C++）＋
   D88 層を載せる現実性も無い。決定: DOS は P8PBASIC の
   ターゲットとしない。build.sh / build.bat は冒頭で理由と
   代替（build-host.sh / build-embed.sh）を明示して停止する
   ようにした（リンク段階の不可解な失敗を排除）。スクリプト
   自体は上流との差分を最小化するため残置する。P8 の現行
   ターゲットはホストCLIと埋め込みエンジン。

## D: 文書化した近似（維持）

6. **文単位ポンプ**（src/vessel.c PUMP_SLICE = 16,667 サイクル）
   BASIC の1文ごとに固定量のエミュレーション時間を進める。
   実機では文の実行時間は内容で変わるため、これは時間の近似。
   根拠: MA2026 の体験（ロード中の BGM、割り込み駆動の演奏）は
   この粒度で実機と一致することを QUASI88 差分テストで確認済み。
   サイクル精度の解釈実行は目標にしない（DESIGN の範囲外）。

7. **hal_poll のペーシング**（src/halp8.c、64文ごと）
   埋め込みHALが音声リードを見て眠る間隔。2秒リングが約0.27秒分の
   ポンプを吸収する前提で、コード内コメントに根拠あり。ホストHAL
   では無効（オフライン最速）。近似ではなくホスト側の実行制御。

8. **XDE 転送時間**（src/vessel.c XDE_SECTOR_CYCLES = 133,333）
   約30セクタ/秒。QUASI88 の実測（約35ms/セクタ）で校正した値。
   実機のシーク時間まではモデル化しない。

9. **SOUND 文はビーパー近似**（src/exec.c、P9PBASIC 由来）
   MA2026 は使わない。PC-88 の SOUND は音源ボード前提で、
   器の OPNA へ写すのが正道だが、需要が実証されるまで近似で維持。

10. **ADPCM-A 固定リズムROMは分離点のみ**（docs/DESIGN.md §音楽再生）
   MA2026 同梱 PMD はサンプルRAM駆動で固定レイアウトを使わない
   ことを実測済み。他タイトルで必要になったら供給部を実装する。

11. **VRTC ハンドラのチェーン先 0xE808 は EI;RET スタブ**
    実機では BASIC ROM のハンドラへチェーンする。器には ROM が
    無いためスタブで受ける。PMD のフェード／効果音処理は器側で
    完結しており、MA2026 の挙動に差は出ていない（実測）。

15. **FFDE サービス1のロード先は ADPCM-B DRAM**（src/vessel.c
    vessel_dram_load、src/opna_ymfm.cpp）【2026-11-20 訂正・H-2】
    サービス1のネイティブ代行は PCM データブロックを YM2608 の
    ADPCM-B DRAM（256KB、オフセット0から）へ直接書く。実機の
    NEOMSC はバンク1レジスタ経由のバースト書き込みで同じ DRAM を
    埋める（転送時間は項目8で近似）。PMD の PCM パートはバンク1
    （制御 reg 00H、delta-N）= ADPCM-B で再生する。以前は誤って
    ADPCM-A 側へ書いており、MA2026 の実測ではデータは一度も
    読まれていなかった。
    リズム音源（ADPCM-A）はチップ内 ROM で、ホスト側の別供給が
    前提（項目10）。未供給の間は常にゼロを読み出す。
    回帰テスト: tools/dramload_test.c。

16. **漢字ROMポート E8–EF と代替フォント**（src/vessel.c、
    src/kanjifont.c）【2026-11-20】
    ゲスト（NEOMSC/XDD）は日本語テキストをグラフィック面へ
    描く際、漢字ROMポート経由でグリフを読む。未実装の間は
    読み値が 0xFF になり、16×16 の塗りつぶしになっていた。
    実装: OUT E8/E9 = ROM1 アドレスラッチ（下位/上位）、
    EC/ED = ROM2、EA/EB は受理して無視（実測では EA は常に
    E9 と同値、EB は常に 0x80）。IN E9 = グリフ左半分、
    IN E8 = 右半分（行はアドレス下位ニブル、ゲストが行ごとに
    再ラッチ）。アドレス配置は QUASI88 の kanji2addr（公開
    されたハードウェア挙動記述）に従うビット詰め配置で、
    バンク0=非漢字+第1水準、バンク1=第2水準。
    1バイト文字（JIS X 0201）は実ROM同様のフラット配置:
    コード C のグリフはストリームオフセット C×16 の16バイト
    （ストリーム = テーブルを [index][行×2+半分] 順に平坦化
    したもの）。XDD のテキストプロッタは addr = C×8 をラッチし
    (E9,E8) ペアで8回読む = グリフの16行そのもの。QUASI88 の
    ステータス描画も同じ読み方をする（&kanji_rom[0][c * 8][0]
    から1バイト/行で16行）。当初 index=コード に置いたところ
    XDD が描く ASCII 文字列（MA2026 の
    "Presented by MEGAFEPPS,2026"）が文字化けしたため、
    2026-11-20 にフラット配置へ訂正（実機報告で発覚、
    ハーネスで修正確認済み）。
    フォント実体は NEC ROM の流用ではなく、パブリック
    ドメインの東雲フォント（しののめ、JIS X 0208 16×16 と
    JIS X 0201 8×16）から生成した代替フォント
    （tools/gen_kanjifont.py）。NEC の ANK 特殊記号とは一部
    字形が異なる（状態表示行の記号類のみ、本文は問題なし）。
    回帰テスト: tools/kanjifont_test.c（トレース実測の配置を固定）。

## V: 検証不足（実装ではなく検証の課題）

12. **FFDE サービス2/3**（src/exec.c）: 実ハンドラへ中継しており
    実装は本物。2026-11-19 に検証して以下が確定した。
    - サービス2は「到達不能」ではなかった。menu の *PLAY は
      (0xFFFC)=&HB1（YM2203系）の時だけサービス0で読み、SB2
      構成（&HB2）では全曲がサービス2（XDE 2, packed, PL, &H5500）
      でロードされる。つまり出荷構成の通常経路であり、使用実績
      として検証済みだった。旧記録（RD=1 で到達不能）は誤り。
    - サービス3（スタッフロ―ル）は menu 2990行「Roll」が発動
      （最終曲の終了／キー割り込み）。ハンドラ（0xA83B）は
      サブ機能 8=スクロール、9=作業ポインタ登録、10=テキスト
      イメージ消去、11=モード登録、0–7=色＋文字列描画。
      描画先はグラフィック面ではなく**ゲストテキストイメージ
      （0xF3C8）だけ**で、文字列は 0xCA00 のフォントで
      ドットマトリクス化されセミグラフィックコードとして
      描かれる。当初は描画パスの使う ROM 文字列評価器
      （0x11D3）が未代行で、古い数値記述子の指す先を描く
      本文無関係の固定パターン（1728 バイト）になっていた。
      評価器をトラップで代行してからは本文依存の描画
      （プローブの固定データで 384 バイト、別本文では 348）
      を対照実験で確認した（tests/probes/PROBE53.BAS、
      Tier A で回帰固定）。
    - 表示側も上の一般化 4 の合成で解決済み（2026-11-19）。
      アプリ側のセミグラフィック・ドット描画はホストの残作業。

13. **言語仕様の「推定」2件**（docs/TOKEN-FORMAT.md）:
    FF82 RIGHT$ と FF85 INT。どちらも MA2026 が使い、表示結果が
    実機と一致することまでは確認済みだが、単独の実機照合は無い。
    他タイトル対応の際に QUASI88 で照合する。

14. **PROBE43 の 0x9CBC ポーリング**: PMD 演奏中に XDD 8 を重ねる
    非実機的な構成でのみ起きる器側の観察事項。実機構成では
    発生しないため、エンジンではなくプローブ側の既知事項とする。
17. **カラーパレットポート 54–5B と表示モードビット**（src/vessel.c、
    src/halp8.c、src/engine.c）【2026-11-20、実機動画の報告で発覚】
    ポート 0x54–0x5B への書き込みが未実装で、ゲストが設定する
    アナログパレット（512色）を全て捨てていた（グラフィックは
    常にデジタル8色で描かれ、アトラクトCGの肌がマゼンタに
    化けた）。実装は QUASI88 pc88main.cpp の公開挙動に従う:
    ポート 0x32 のビット 0x20 が立つ間はアナログ2回書き込み
    （bit6=0: B=(d&7), R=(d>>3)&7、bit6=1: G=d&7）、落ちている間は
    デジタル（bit0-2 = G/R/B）。同ビットは本物のROM初期化が
    立てるもので、ゲストの読み書き（RMW）で保持されるため、
    vessel の IN 0x32 初期値を 0x20 とした。BASIC の PALETTE 文
    （hal_palette）も同じレジスタへ写像し、OUT 直接書き込みと
    一元化した。表示は成分 0–7 を ×255/7 で拡大。QUASI88 の
    実測フレームと色一致を確認済み（肌 (255,218,182) 等）。

18. **SCREEN 表示スイッチの訂正**（src/graph.c）【2026-11-20】
    第2引数 sw の解釈を訂正: 0=グラフィックのみ、1=重ね合わせ、
    2=テキストのみ。従来は sw=2 を「重ね合わせ」としており、
    *SELECT（SCREEN 0,2）で CG がリストの下に残った（実機報告）。
    実機相当（QUASI88）では *SELECT は黒地にテキストのみ、
    アトラクト（SCREEN 0,0）は GVRAM の CG+*TITLE パネルのみで
    テキスト面のリストは出ない。

19. **【未解決】XDD のデータ参照形が何も描かない**
    （2026-11-20 発見、要調査）
    XDD 1/5/6 と XDD 7 のデータ参照形（`XDD 5,3,1,41,6;0,0`
    のように曲番号・種別で曲DBを参照する形）が、vessel では
    何も描かない。文字列リテラル形（XDD 3/4/6/7）は正常。
    MA2026 のアトラクト *TITLE パネル（曲タイトル・コメント）が
    この形のため、実機では出るパネル文字が vessel/アプリでは
    欠落する（LINE のボックスと XDD 7 リテラル形のクレジット
    文字列は描かれる）。切り分け済みの事実: 中継の引数評価は
    正しい（P8P_TRACE_EXT 実測）、曲DB は 0x2000 に実データが
    残りポインタ表（0xA543〜）も PROBE18 の実測値と一致、
    ハンドラは引数を途中まで取得する。NEOMSC ハンドラ内部の
    参照解決のどこかで vessel 環境と食い違う。プローブの
    覆盖はリテラル形のみで、この形の回帰プローブ追加が先決。
