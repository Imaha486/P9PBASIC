# NEOMSC 契約メモ（器が満たすべき外部インターフェース）

作成: 2026-11-17 / 改訂: 2026-11-18（ロードベース・文エントリ・
VRAM バンキング・割り込みレベルを実機規約に合わせて全面訂正）
方法: z80dis 逆アセンブル（NEOMSC.lst、作業領域に保管）＋
QUASI88 モニタでのライブトレース＋器での動的検証。
**アドレスはすべて実機（0x9900 ベース）の値を記す。**
逆アセンブル一覧のアドレス欄は旧ベース（0x9800）で振られているため、
実機アドレス = 一覧の欄 + 0xFC。

## 基本情報（実測）

- NEOMSC は PC-88 BSAVE 形式ファイル: 先頭 4 バイトが
  **[ロードアドレス u16][終了アドレス u16] = [0x9900][0xA95E]**、
  本体は file[4..]。ファイルサイズ 4352 バイト。
- **ロードアドレス 0x9900、エントリ（初期化）は 0x9900**
  （ファイルオフセット 3: `F3 3E C3 32 A1 EE ...`）。
  BLOAD はヘッダのアドレスへ置く。MENU.ALP 120 行の
  `CLEAR,&H97FF`（上限+1 = 0x9800）はヘッダ値と一致しないが、
  実機 BLOAD ではヘッダが勝つ（QUASI88 の実機 RAM ダンプで
  0x9900 配置が 4255/4352 バイト一致、0x9800 配置は 62/4352）。
- 初期化は EEA フック 3 つを植え、(0xE6B9)=0xFF、(0xE6B4)=0xE8、
  CALL 0x6F6B（BC=0x5019, HL=0xA6DB、登録系。器では無動作で代行）、
  SB2 探査（OUT (0xA8),0xFF / IN (0xA9)）を行い RET で戻る。
  曲テーブル（後述）も初期化が書く。

## 文エントリ（EEA フック、QUASI88 でライブ確定）

| ベクタ | 飛び先 | 文 | 入口レジスタ（実測） |
|---|---|---|---|
| 0xEEA1 | **0x9E5C** | **FFDD**（表示/データ） | BC=0xEEA1、HL=第1引数のトークン位置、A=第1引数のトークンバイト |
| 0xEEA4 | **0x994D** | **FFDE**（ディスク/データ） | BC=0xEEA4、HL=0xE69C（インタプリタ内部定数）、A=第1引数のトークンバイト |
| 0xEEA7 | **0xA6DB** | **FFDF**（音楽制御） | BC=0xEEA7、HL=コマンド文字の位置、A=その文字 |

- **ROM ディスパッチャは第1引数を先に評価する**: FFDD/FFDE の
  ハンドラ先頭は評価ヘルパ（0x9F84）を呼び、(0xEC41) の値を得て
  分岐する（FFDD: CP 8 / CP 9、FFDE: LD (0x99DE),A）。先頭の
  呼び出しには RST 8 が先行しないため、第1引数の値はディスパッチャ
  側が (0xEC41) に入れてから飛んでくる。**器の中継は呼び出し前に
  第1引数を (0xEC41)/(0xEC42) と EC44 スクラッチブロック
  （[型=2][lo][hi]）へ priming すること**（vessel_prime_arg）。
- FFDF ハンドラはコマンド文字を (HL) から自分で読む（入口で
  `LD A,(HL); INC HL`）。実機トークン列は
  `FF DF 20 'R' 2C 0C 00 CA ...` の形（0x20 は区切り空白）。

## RST 8 サービス 0x2C（引数評価、実測で確定）

ハンドラ内の後続引数の評価に使う。ROM 側評価器は自身のポインタで
進むため、このサービスは **HL の再同期** を担う:

1. 空白を飛ばす。HL のバイトが ',' でなければ、**直前に消費済みの
   トークン 1 個分を読み飛ばす**（文字列・数字トークン列・
   0x0F/0x1C/0x0C/0x0B/0x0E の固定長形式・0x1D MBF 単精度・
   0x1F MBF 倍精度を判別）。
2. 空白と ',' を 1 個まで飛ばし、次の式を評価する。
3. 値を **(0xEC41)=lo、(0xEC42)=hi** に置き、あわせて EC44
   スクラッチブロック（[型=2][lo][hi]）にも書く。HL は消費した
   引数の直後を指して戻る。

読み取り側: ROM 0x18A3 → A に下位バイト、NEOMSC 0xA794 → DE に
16 ビット値（どちらも (0xEC41) 系から読む。0xA794 は NEOMSC コード内
の絶対アドレスで、実体は ROM 評価器へ連鎖するため器ではトラップで
代行する）。

## FFDF ハンドラ（0xA6DB）

- HL = コマンド文字。文字ごとに分岐し、引数は RST 8 svc 0x2C /
  0xA794 で自ら読む。復帰時 HL は消費分進む。
- PMD エントリ: **AA00=演奏（P）、AA03=停止（S）、AA06=フェード
  （F,n）、AA09=効果音（E）**。
- PMD ワークレイアウト（AA00 起点、バンドル PMD のバイト列で確定）:
  ジャンプテーブル 5 本（+0/+3/+6/+9/+0x0C）、
  +0x0F mmlbuf（R のアドレス）、+0x11 tondat、+0x13 efftbl
  （K のアドレス）、**+0x15 vrtcfook（JP 命令スロット、
  既定は JP 0xE808）**、+0x18 getss JP、+0x1B getfv JP、
  **+0x1E pcmflag、+0x1F effflag、+0x20 status、+0x21 status2**。

## FFDE ハンドラ（0x994D）

- 先頭 `CALL 0x9F84; LD (0x99DE),A`（サービス番号を保存）。
- **サービス 0** = (0, ディスク, 論理トラック, セクタ, セクタ数,
  アドレス) の生セクタ読み。器は vessel_disk_read でネイティブ代行。
- **サービス 1** = (1, ディスク, 開始論理トラック, トラック数) で
  予約領域から ADPCM ブロックを SB2 の ADPCM-A サンプル RAM へ
  一括ロード。器は vessel_dram_load でネイティブ代行
  （論理トラック 1 先頭は "ADPCM DATA for PMD ver.4.4-" ヘッダ＋
  サンプルテーブル）。PMD が触るのは ADPCM-A（バンク0 の
  0x10–0x1F）のみで、ADPCM-B（バンク1）はこの曲では不使用。
- **サービス 2** は出荷構成では到達不能（MENU.ALP 385 行の RD=1
  強制で *PLAY は常にサービス 0 経路）。サービス 3 はスタッフ
  ロール表示。2/3 は器でも実ハンドラへ中継する。
- **第2引数 = ディスク選択**（実機ではドライブ、器では .D88 に
  同梱されたディスクイメージの番号）。MA2026A.D88 は
  "MusicArena2026 A"（イメージ 0）と "MusicArena2026 B"
  （イメージ 1）の 2 枚組で、PMD 本体・ADPCM ブロック・CG・
  曲 DB は A、**曲データはすべて B**（ローディング BGM の
  *BGMP も *PLAY の全曲ロードも第2引数 = 1）。この引数を無視
  して常にイメージ 0 を読むと、PMD が A 側の別データ（文字列や
  CG のバイト列）を曲として演奏してしまう — 実機ビルド 91 の
  音声ノイズと「1曲目が無音」という誤認の真因（2026-11-18、
  QUASI88 のモニタで *BGMP の XDE に停止させて特定。QUASI88 は
  イメージ 1 をドライブ 2 に割り当てないとこのロードで
  0x9CBC のポーリングに留まり続ける）。

## FFDD ハンドラ（0x9E5C）

先頭 `CALL 0x9F84`（= priming 済みの第1引数）で分岐:

- **=8: CG ロード**。入口（0xA4A9）: ストリームの次バイトが ','
  なら CALL 0x9BF5 でアドレス引数を DE へ、なければ DE=0x1000。
  IY=DE（CG データ）、IX=0xC000（VRAM ウィンドウ基点）。
  (0xAA15) に RET;EI（C9 FB）を置き、ポート 0x31 に (0xE6C2)
  シャドウ経由で bit1 を立て、OUT (0xE6),2 の後、展開器
  （0xA4EA）を呼ぶ。出口でポート 0x31 と (0xAA15)=JP 0xE808
  （C3 08 + PMD 自身の E8 バイト）を復元。
  - 展開器: まずヘッダを変換ルーチン（0xA663）経由で読み、
    ワーク表を 0xA6D8 に構築（(0xA6D6) に IX を退避）。
    本体はコマンドバイト列: **0x00 で終了**、(cmd>>5)&7 で
    セグメント種別を選び、マスク長つきプレーン書込みを行う。
    書込みは格納ヘルパ（0xA6BD）: EXX; DI; OUT (C),A
    （C=0x5C/0x5D/0x5E でプレーン選択）; LD (HL),A
    （HL'=ウィンドウ宛先）; ADD HL,DE（ストライド）; DEC B;
    EXX; RET NZ。B 尽き時は行/ページ簿記をして OUT (0x5F)、
    EI、RET。
- **=9: 曲 DB パース**。DE の指す DB テキスト（CR/LF/CR 区切り、
  0x1A 終端）を走査し、ポインタ表を **0xA447** から構築する。
  DB が先にロードされていないと走査が暴走する。
- **その他（1/4/5/6/7 等）: パラメータコレクタ＋描画系**。
  コレクタは引数を順に (0xA3FD)←先頭値、(0xA3FC)←arg1、
  (0xA3FB)←arg2、(0x9F96)/(0x9F97)←arg3/arg4（評価ヘルパ内の
  自己書換セル）、(HL)==',' なら文字列引数経路（0xA061）、
  さらに (0xA443)/(0xA444) へ格納し、DB レコード歩行＋描画
  （グリフ描画は宛先ポインタ (0xA3FE)、作業バッファ 0xA400+、
  テキストイメージ 0xF3C8 参照）へ進む。
- テキストイメージはゲストメモリ **0xF3C8**: 25 行 × 120 バイト
  （コード 80 + 属性 40、属性行 r は 0xF3C8 + r*120 + 80）。

## VRAM ウィンドウ（PC-88 バンキング、QUASI88 の実装で照合）

- CPU **0xC000–0xFFFF** は VRAM ウィンドウ: 実効アドレスは
  `vram[addr & 0x3FFF][bank]`、bank は **0=B, 1=R, 2=G, 3=メインRAM**。
  選択はポート **0x5C/0x5D/0x5E/0x5F** への OUT。
- ポート **0x32** bit 0x40（EVRAM 拡張アクセス）とポート **0x35**
  bit 0x80（VACCESS）が両方立つと ALU アクセス路になる:
  ポート **0x34**（ALU1）/0x35（ALU2、bit 0x30=モード、
  bit 0–2=比較データ）。書込みモード 0 ではプレーン i ごとに
  制御ペア（ALU1 の bit i / bit i+4）で 00: vram &= ~data、
  01: vram |= data、10: vram ^= data、11: 保持。
  NEOMSC のグリフ複写は ALU1 = CPL(param<<4) を使い、色ビットが
  立つプレーンだけグリフビットを立てる。読込みは 3 プレーンの
  （比較ビットが立てばプレーン値、なければ反転）の AND。
- GVRAM はプレーンごとに 80 バイト × 200 行（16KB）、表示は
  行 2 倍で 400 行。色インデックスは bit0=B, bit1=R, bit2=G
  （テキスト属性 (attr>>5)&7 と同じ並び）。
- **器のコールスタックは 0xC000 未満に置くこと**（器は 0x98F0）。
  ウィンドウ内に置くと、プレーン選択中の push/pop と番地
  センチネルが VRAM へ逸れる（2026-11-18 の XDD 8 暴走の原因）。
  置き場所にも注意: 0xBF00 は PMD のロード範囲（0xAA00–0xC9FF、
  32 セクタ）の内側で、スタック書込みがドライバを静かに壊し
  演奏が無音化した（同日、embed との二分探索で特定）。0x98F0 は
  プログラム自身が予約する隙間（CLEAR 上限 0x97FF と NEOMSC
  0x9900 の間）にある。
- 曲テーブル **0xC800** と演奏中曲データ 0xCA00 はメイン RAM 側の
  実体。ドライバの出口はバンク復元を保証しない（CG 展開器は
  通常出口で G プレーンを選択したまま戻る。OUT (0x5F) は
  ページ枯渇経路にしか無い）。**静止時（文と文の間）はメイン
  RAM が選択されているのが実機の前提**で、器は vessel_pump の
  静止時正規化（EI 復元と同様）で mem_bank=3 に戻す。器の解釈側
  PEEK/POKE とネイティブサービスはフラット RAM を見る。

## 割り込みモデル（PMD88 v3.7 ソース＋実測）

- **IM 2 の対**: ベクタ表（I=0xE9 ページ）+2 = VRTC ハンドラ
  （フェード/効果音、~60Hz）、+8 = OPN ハンドラ（シーケンサ本体、
  OPNA Timer B 駆動: カウンタ reg 0x26、制御 reg 0x27 ← 0x3A）。
  CTC は存在しない。
- reg 0x27 = **0x3A** の内訳: bit1（0x02）Timer B 開始、
  bit3（0x08）Timer B IRQ 許可、bit4/5（0x10/0x20）Timer A/B
  フラグリセット。opnint は出口で 0x3A を書き直してフラグを
  リセットする（"TIMER RESET"）。
- **ポート 0xE4 = 割り込み優先レベル**（QUASI88 の intr モデル）:
  値 & 7（bit3 が立てば 7）。**サウンド割り込みはレベル >= 5、
  VSYNC は >= 2** が必要。PMD の mstart はレベル 5 を、
  **mstop はレベル 2** を書く（(0xE6C3) シャドウにも保存）—
  つまり停止中はシーケンサ割り込みが PIC で止まる。器も
  レベルで配送をゲートすること（これを欠くと XDF S 直後の
  XDD 8 描画中にシーケンサが並行して走り、PCM キーオン処理が
  暴走する。2026-11-18 のステップキャップ多発の原因）。
  ハンドラ側の作法（バンドル PMD の実バイトで確認）: opnint の
  出口はレベル 5 を直書きし、vrtcint の出口は (0xBD2D)（e4out
  セル、rtlset が 5 / mstop が 2 を書く）を復元する。なお
  ローディング BGM は実機では ADPCM ロード（448 セクタ）の間
  鳴り続ける（QUASI88 実測で約 19 秒）。器のネイティブ XDE は
  実転送時間（約 30 セクタ/秒）をポンプ単位で消費し、その間も
  ハンドラ配送と hal_poll のペーシングが回るため、BGM は
  ロード中ずっと演奏される（2026-11-18 修正）。ゲートを外すと
  停止後も opnint が曲を進めてしまい BGM が鳴り続けるが、
  それは実機と違う artefact の方である（同日実測で切り分け
  済み）。かつて「BGM は無音のイントロで終わる」と記録したのは、
  上記のディスク選択ミスで別データを演奏していたためであり、
  本物の BGM（曲 5）は最初から大音量で鳴る。
- ポート **0xE6 = 割り込みマスク**（bit: 0x01=RTC、0x02=VSYNC、
  0x04=SIO、0x80=SOUND、1=許可）。NEOMSC は CG 展開と DB 歩行の
  間 OUT (0xE6),2（VSYNC のみ許可）を書く。
- ポート 0x31 はグラフィック制御（bit1 = 64RAM: 0x8000–0x83FF を
  ウィンドウ化）。NEOMSC は OPNA バンク1 バーストとサブシステム
  OUTI バーストの前後で (0xE6C2) シャドウ経由にトグルする。
  器では未実装（RD=1 構成では不使用）。

## ディスクサブシステム（8255、公開資料＋実測）

PC-88 のディスクはサブ CPU＋FDC のサブシステムで、メインとは
8255（FC=受信、FD=送信、FE=ハンドシェイク、FF=制御）で話す。
NEOMSC は ROM ルーチン（PUTCOM 0x37C9/PUTDAT 0x37D2、器では
トラップ）とポート直接操作（9Cxx の自前転送ルーチン: OUTI
バースト＋FE ポーリング）の両方を使う。器は 8255＋コマンド処理
（00/01/02/03/06/07/12/17/18/23）を D88 バックで再現する。
なお QUASI88 では、D88 のイメージ 1 をドライブ 2 に割り当て
ないと、イメージ 1 宛の XDE ロードで 0x9CBC のハンドシェイク
ポーリングに留まり続ける（A/B を別ファイルに分けて 2 ドライブ
に載せれば完走する。同じロードは器と P88SR でも完走する）。

## 器への要求（まとめ）

1. Z80 コア（superzazu/z80）＋ 64KB 共有メモリ。ただし Z80 バス
   からの 0xC000–0xFFFF は VRAM ウィンドウとして解決し、
   解釈側 PEEK/POKE はフラット RAM を見る。
2. BLOAD は BSAVE ヘッダ（無ければ従来どおり上限+1）に従う。
3. 文中継は EEA ハンドラを上記規約で直接呼ぶ（第1引数の
   priming を含む）。コールスタックは 0x98F0。
4. RST 8 svc 0x2C と外部 CALL（0x18A3、0xA794、PUTCOM/PUTDAT 等）
   をトラップしてネイティブ代行。
5. 割り込みは IM 2 対＋ポート 0xE4 レベルゲートで配送。
   ポート 0x44–0x47 / 0xA8–0xAB を ymfm（YM2608）へ橋渡し。
6. XDE のネイティブ代行は第2引数でディスクイメージを選び、
   実転送時間（約 30 セクタ/秒）を消費する（ロード中の BGM
   演奏と画面遷移の順序が実機と一致するために必須）。

## 動的検証（2026-11-18、現行器）

- PROBE2（FFDF 中継回帰）: (0xAA0F)=0xCA00、(0xAA13)=0xC000 ✓
- PROBE18（DB ロード＋XDD 9）: ポインタ表が実値で埋まる ✓
- PROBE19/44（XDE で CG ロード＋XDD 8）: ステップキャップなしで
  完走し、タイトル CG が VRAM プレーンに描画される ✓
- MENU.BAS 全体フロー: ステップキャップ 0 件、アトラクトが
  曲ロード＋演奏を循環 ✓
- 埋め込み（embed）ハーネス: XDD 8 直後の VRAM に
  「MUSIC ARENA 2026」タイトル CG が欠けなく描画され、
  p8_frame 合成でも表示される ✓
- **音声の真正性（2026-11-18 追加検証）**: QUASI88（A/B を
  2 ドライブに分割）で実機手順を実測 — 待機画面（バナー＋
  PCM メッセージ）のまま BGM が約 7 秒で始まり約 19 秒鳴り、
  CG＋リストを経てアトラクト（左 CG・右タイトル文字）で
  フル音量の曲へ。器の embed でも同順序（無音 → BGM 大音量
  → 静かな残響 → アトラクト大音量）を確認し、タイトル CG の
  VRAM 非ゼロ数 [4555, 4770, 5394] が従来検証と一致。
  PROBE5（曲 5 単体）は最初から大音量で鳴り続ける。
