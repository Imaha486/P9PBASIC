# NEOMSC 契約メモ（器が満たすべき外部インターフェース）

作成: 2026-11-17 / 方法: z80dis によるフロー追跡逆アセンブル
（カバレッジ 4233/4352 バイト）。実測と推定を分けて記す。
一覧表の根拠は本文末尾の出典。

## 基本情報（実測）

- ロードアドレス **0x9800**、サイズ 0x1100（4352 バイト）。
  根拠: 初期化コードが自分自身の領域内のアドレス（0x994D 等）を
  フック先として書き込むこと、CLEAR ,&H97FF で BASIC 側が
  0x9800 以降を保護していること。
- エントリは 0x9800。初期化後に RET で BASIC へ戻る。
- 先頭 3 バイト（0x9801–9803）はコードではない（データ/署名領域）。

## 初期化（0x9800–0x9850、実測）

1. DI の後、RAM ベクタ 3 つに JP 命令（0xC3）を書き、飛び先を設定:
   - 0xEEA1 → 0x9E5C
   - 0xEEA4 → 0x994D
   - 0xEEA7 → 0xA6DB
2. ワークエリアへ書き込み: (0xE6B9)=0xFF、(0xE6B4)=0xE8。
3. BC=0x5019 で CALL 0x6F6B（外部ルーチン、役割は未確定）。
4. サウンドボードII探査: OUT (0xA8),0xFF → IN (0xA9)。
   戻り値が 1 のとき（SB2 検出時）に 6 箇所のセルへ 0xAC を書き込む
   （0x9B95, 0x9BC9, 0x9BD2, 0x9AD9, 0x9AE3, 0xA82D。
   モード切替セル／命令オペランドとみられる。動的検証で確認）。
5. EI、RET。

## フックベクタ 3 つ（入口コードからの観察）

| ベクタ | 先 | 入口の振る舞い（実測） | 役割の推定 |
|---|---|---|---|
| EEA1 | 9E5C | A をポート 0x31 と (0xE6C2) へ書き、0xAA15 に JP 命令コードを置いて戻る | PMD 連携（割り込み連鎖/ドライバ状態） |
| EEA4 | 994D | A が 0x11 未満なら E=A として 0x9C01 / 0x9C05 を呼ぶ（テーブル駆動） | 番号 0–16 の機能ディスパッチャ（拡張関数群か） |
| EEA7 | A6DB | HL を逆向きにたどる XOR ループ、0xA82B を DE=0x21 / 0xA0 で呼ぶ | ディスク読み取り系（文ディスパッチの可能性も） |

どのベクタが FFDD/FFDE/FFDF のどれに対応するかは、器での動的トレースで確定する。

## BASIC 側サービスへの依存（器がトラップして提供するもの）

- **RST 8（inline バイト付き）**: 使われるのはサービス **0x2C のみ**、
  27 箇所。意味は上記「次の引数を評価し (0xEC41) ディスクリプタへ」
  で確定。器のトラップは区切りを読み飛ばし、合成トークン列の
  リテラルを評価してディスクリプタ（作業域 0xEC44 を指すよう
  (0xEC41) を初期化）を書く。
- **ROM 0x18A3**: (0xEC41) ディスクリプタから評価値の下位バイトを
  取得 → A。FFDF の F/E/M で使用。器ではトラップで代行。
- **ディスクサブシステム ROM ルーチン**（公開資料で同定）:
  - CALL 0x37C9 ×2（PUTCOM=0x37CC の直前エントリ）
  - CALL 0x37D2 ×7 = PUTDAT（A をサブシステムへ送信）
  - GETDAT=0x3847 への直接呼び出しは検出されなかった（ポート直読みか）。
- その他の外部 CALL/JP（要同定、動的トレース対象）:
  0x00C1, 0x01B6, 0x029A, 0x03B3, 0x06C9, 0x11D3, 0x1796, 0x18A3(×6),
  0x193E, 0x1B9D, 0x2256, 0x37C9, 0x56CC, 0x6000, 0x610A, 0x6F6B,
  0xF6E6（JP）, 0xA90D（RAM スロットの可能性）。
  一部はデータ領域の誤読の可能性がある。

## ディスクアクセスの実像（公開資料＋実測）

PC-88 のディスクは独立したサブシステム（サブ CPU＋FDC）で、メイン側とは
8255 経由（ポート FC=受信データ、FD=送信データ、FE=ハンドシェイク、
FF=8255 制御）でコマンドプロトコルを話す。NEOMSC は ROM ルーチン
（PUTCOM/PUTDAT）とポート直接操作（IN (0xFE) ×18、OUT (0xFF) ×26 等）
の両方を使う。器はこの 8255＋サブシステムをポートレベルで再現し、
コマンド（02h リードデータ＋03h センドデータ等）を D88 イメージで
処理すればよい。FFDE のセクタ読みはこの経路で NEOMSC 自身が行う。

## PMD との接続（実測）

- PMD エントリ（FFDF ハンドラ 0xA5DF からの呼び出しで確定）:
  - **0xAA00 = 演奏開始（P）**、**0xAA03 = 停止（S）**、
    **0xAA06 = フェード（F）**、**0xAA09 = 効果音（E）**。
  - データスロット: 0xAA0F（R コマンドのアドレス）、0xAA13（K コマンドの
    アドレス）、0xAA1F（ES の値）、0xAA1E（M 処理で 1 を書く）。
- 0xAA15 に JP 命令コードを設置（飛び先は PMD 側/別ルーチンが設定）。
- PMD 本体はディスク予約領域から 0xAA00 へ FFDE で読み込まれる
  （MENU.ALP 260 行）。

## 拡張文ハンドラの規約（2026-11-17 追加、実測）

PMD88 公式ローダ（pmd1.bas / pmd2.bas、KAJA 作）が
`BLOAD "mc",R` の後に FFDF を使うことから、mc（PMD の常駐部）と
NEOMSC は同じインタプリタ規約に従うと分かる。両者で確認した規約:

- **FFDF ハンドラ**: NEOMSC では **0xA5DF**、mc では 0x9010
  （ロード先 +0x10）。入口で **HL = トークン列中のコマンド文字への
  ポインタ**。ハンドラが文字を読み、引数も自分でトークン列から
  読む。復帰時 HL は消費した分だけ進む。
  - P → CALL AA00、S → CALL AA03（引数なし）。
  - F,n → RST 8 (0x2C) でカンマを読み飛ばし、ROM 0x18A3 で値を
    得て JP AA06。E,n / E,12 / E,15 も同様（ES は (0xAA1F) へ値）。
  - R,addr / K,addr → 0xA794 で 16 ビット値を DE に読み、
    (0xAA0F) / (0xAA13) へ格納。M,... は座標等を 0x18A3 で読む。
- **RST 8 サービス 0x2C = 「次の引数を評価し、(0xEC41) の指す
  ディスクリプタ [型, lo, hi] に残す」**（カンマ読み飛ばしを含む）。
  ハンドラ側の読み取り: 0xA794 = 評価値の 16 ビット取得（→ DE。
  ファイル上は未完成のスロットで、登録コール 0x6F6B が ROM 側で
  実体を当てるものとみられ、器ではトラップで直接代行する）、
  ROM 0x18A3 = 評価値の下位バイト取得（→ A）。
  0xA8A6 も同様の予約スロット（ファイル上は NOP 列）。
- **FFDE サービス 0 の引数意味が確定**（ディスク実データで検証）:
  (0, ドライブ, 論理トラック=C*2+H, セクタ, セクタ数, アドレス) の
  生セクタ読み。論理トラック 29/セクタ 1/32 セクタ → 0xAA00 に
  PMD のジャンプテーブルがそのまま現れる。器は vessel_disk_read で
  ネイティブ代行する（ディスクサブシステムのポートモデルと同じ
  意味論の、ステートメントレベルの等価実装）。
- **FFDF の中継は実装・検証済み**（2026-11-17）: インタプリタが
  評価済み引数を PC-88 トークン列に再合成し、HL=コマンド文字で
  0xA5DF を呼ぶ。R/K は (0xAA0F)/(0xAA13) への格納を確認、
  F は PMD 0xAA06 へ到達。P/S は PMD 本体に入るが、タイマ割り込み
  待ち（0xBCC7）で止まる — 割り込みモデルは次段階の課題。
- **FFDE サービス 1 の意味が確定**（2026-11-17、Phase 5）:
  (1, ドライブ, 開始論理トラック, トラック数) で予約領域から
  ADPCM ブロックを SB2 のサンプル RAM（OPNA の ADPCM-A 外部
  メモリ）へ一括ロードする。MA2026 の呼び出しは (1,0,1,28) の
  1 回のみ: 論理トラック 1 の先頭は "ADPCM DATA for PMD
  ver.4.4-" ヘッダ＋サンプルテーブルで、PMD の PCM ドライバは
  このブロックを DRAM から読んで鳴らす。器は vessel_dram_load で
  ネイティブ代行し、ymfm の ACCESS_ADPCM_A の裏側に置く。
  実測: デモ曲の PCM パートが鳴り、チップの A メモリ読みが
  流れる（従来の無音区間のうち演奏区間の音圧が変化）。
  なお PMD が触るのは ADPCM-A 系（バンク0 の 0x10–0x1F）で、
  ADPCM-B（バンク1）への書き込みはこの曲では皆無だった。
- **FFDE サービス 2 は出荷構成では到達不能**（2026-11-17）:
  MENU.ALP 385 行の RD=1 強制により &HFFFC=&HB1 となり、
  menu の *PLAY は常にサービス 0 のフロッピー経路を取る。
  サービス 2（DRAM→ゲスト複写）の唯一の呼び出しは SB2 RAM
  モード時のみ。サービス 3 はスタッフロール表示（到達するが
  表示系のため器ではトレースのみ）。
- **曲テーブル (&HC800)** は NEOMSC 初期化が書き込む
  (TRK, SEC, RS, 0) ×曲数。先頭は (44,13,0) のダミー、
  #1=(1,1,25) は ADPCM ブロック先頭そのものを指し、SB2
  実構成でも「演奏」するとシーケンサは回るが無音になる
  （RD=1 構成の出荷時クセとして器でも同じ挙動を確認）。
- EEA4 (0x994D) は文ハンドラの入口ではない（サブシステム
  セッション系の内部入口）。FFDD/FFDE の文ハンドラ本体は
  未同定のまま: 0x9851/0x9962/0x9D60 一帯は演奏中のデータ
  供給（フィーダ）＋表示エンジンの部品群で、文入口ではない
  ことを逆アセンブルで確認した。表示系は HAL 側の VRAM
  マッピングで受ける方針（Phase 6）。
- 0x9851 一帯は文ハンドラではなく**演奏中のデータ供給まわり**
  （割り込み駆動）と判明（9F84 は呼び出し元へ戻らない）。
  FFDD の文エントリは引き続き未確定で、当面は無動作（トレースのみ）。
- **0x9F84** は (BC) の指す曲テーブルエントリを処理するルーチン
  （CTC 設定＋音色テーブルのストライド 0x50 コピー、戻り値 A は
  エントリ種別）。FFDD 系ディスパッチャが 2 つある:
  0x9851（9F84 の戻り 0–3）と 0xA73F（同 8/9/10/その他、9 は
  値を (0xA8D3) へ、10 はテキスト VRAM クリア 0xF3C8〜）。
  FFDD/FFDE の文エントリそのものは未確定（次段の動的トレースで確定）。
- 未解決: 実機インタプリタがベクタ経由で文ハンドラへ到達する正確な
  経路。mc の EEA7 植え付け先 0x900C は `LD (0xEEA8),HL; RET` の
  スタブで、ハンドラ本体は +6 の 0x9010 にある。我々のインタプリタは
  独自ディスパッチ（XDD/XDE/XDF）を持つので、中継はハンドラを
  上記規約で直接呼べばよく、この未解決は中継の障害にならない。

## ワークエリア共有（実測）

- 0xE6C2: 読み書き 20 箇所。ドライバ状態バイト（BASIC 側 PEEK 対象の
  &HAA20/&HAA21 とは別。こちらは BASIC ワークエリア側の状態）。
- 0xEC41: 読み ×3。0xF416: 書き ×1（テキスト VRAM ポインタ近傍）。
  0xFE69: 書き ×1。

## ポート使用（即値、被覆コード内の実測）

- OUT: 0x31(×16), 0x32(×8), 0x34(×4), 0x35(×8), 0x5F(×4), 0xA8,
  0xE6–0xEB, 0xF8, 0xFC–0xFF
- IN: 0x32(×8), 0x46, 0xA9, 0xE8, 0xE9, 0xF8, 0xFC–0xFE(×18)
- 0x34/0x35 は CTC（タイマ割り込み＝演奏クロック）系と推定。
  0x31/0x32 は割り込み制御・サブ CPU 通信系と推定（要同定）。

## 器への要求（まとめ）

1. Z80 コア（superzazu/z80）＋ 64KB 共有メモリ（BASIC の PEEK/POKE と同一）。
2. BLOAD "NEOMSC",R で 0x9800 へロードし Z80 をエントリから実行、
   RET で BASIC へ復帰。
3. EEA1/EEA4/EEA7 ベクタ呼び出しをインタプリタ側から Z80 へ中継
   （XDD/XDE/XDF スタブと FF 関数が接続点）。
4. RST 8 (svc 0x2C) と外部 CALL 先をトラップし、ネイティブサービスで
   代行（ディスクは 8255 ポートモデル＋サブシステムコマンド処理）。
5. CTC 相当のタイマ割り込みで PMD を進める。ポート 0xA8–0xAB /
   0x44–0x45 を YM2608/YM2203（ymfm＋リズム音源）へ橋渡し。

## 動的検証（2026-11-17、superzazu/z80 上の最小ハーネス）

- 初期化は 35 ステップで完走。外部トラップは CALL 0x6F6B の 1 回のみ
  （引数 A=0xE8, BC=0x5019, HL=0xA6DB — 登録系コールと推定、器では
  ログ＋無動作で代行可能）。EEA ベクタ 3 つの RAM 上の書き込みも確認
  （C3 5C 9E / C3 4D 99 / C3 DB A6）。
- EEA1 ハンドラ（9E5C）に A=0 で入ると OUT (0x31),A を実行し
  7 ステップで復帰（静的解析どおり）。
- EEA4 ハンドラ（994D）に A=0 で入るとディスクサブシステム側へ進む:
  8255 制御（OUT (0xFF) = 0x00, 0x91）、RST 8 svc 0x2C を経て
  FC/FD/FE のハンドシェイクに入る。器の仮想サブシステムは
  8255 ハンドシェイク状態機械をポートレベルで再現する必要がある
  （FE が定数応答ではループする）。
