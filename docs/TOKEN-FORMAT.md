# PC-88 N88-BASIC トークン形式（MA2026A.D88 の実物から実証）

作成: 2026-11-17 / 対象: MENU.ALP（69 行）、menu（265 行）を全行デトークナイズして検証

PC-98（N88-BASIC(86)）版とはコード表が異なる。以下はすべて実物との
突き合わせで確認したもの。デトークナイザは `tools/p88_detok.py`、
抽出器は `tools/p88_extract.py`。

## 行形式

```
[link u16 LE][行番号 u16 LE][本体][0x00]
```

- link は次行のファイル先頭からのオフセット。ただし実物では ±1
  ずれる行があるため、パーサは link±2 の範囲で妥当な次ヘッダを探す。
- 最終行も link で区切る。最終行の link は自分の 0x00 終端の直後
  （プログラム終端の `00 00`）を指すので、本体は link−1 まで。数値
  定数のペイロード（MBF の 1.0 = `00 00 00 81`、行番号参照の上位
  バイトなど）は 0x00 を含むため、本体を 0x00 で探して切ることは
  しない。link±2 の範囲で「終端 0x00 + `00 00`」を探し、無ければ
  （終端の直後でファイルが切れている場合）終端 0x00 だけを探す。
  どちらも無いときに限り、最初の 0x00 までを本体とする。終端の
  0x00 は本体に含めない（以前は最終行だけ終端が本体に残り、変換
  結果の末尾に NUL または `<00>` が出ていた）。
- 本体は MS-BASIC 系トークン列。変数名は素の ASCII（型接尾辞 $ % ! # 付き）。

## 数値・記号

| コード | 意味 |
|---|---|
| 0x0B | &O + u16 LE |
| 0x0C | &H + u16 LE |
| 0x0E | 行番号参照 + u16 LE |
| 0x0F | 1 バイト整数 |
| 0x11–0x1A | 数字 0–9 |
| 0x1C | int16 LE |
| 0x1D | 単精度（MBF 4 バイト） |
| 0x1F | 倍精度（MBF 8 バイト） |
| 0xF0–0xFE | 演算子: > = < + - * / ^ AND OR XOR EQV IMP MOD \ |
| 0xF5 | 式中では * （乗算）。GOTO/GOSUB/RESTORE の引数位置ではラベル参照マーカー（直後にラベル名 ASCII） |

MBF 定数の復号（変換器とデトークナイザ共通。MA2026 の 2 プログラムには
0x1D / 0x1F / 0x0B の実例が無く、標準の MBF 定義に基づく）:

- 値 = 符号 × 0.1fff…（2 進）× 2^(exp−128)。仮数は [0.5, 1) の小数で
  先頭の 1 は格納されず、そのビット位置（最上位仮数バイトの bit7）が
  符号。exp = 0 は 0。1.0 は exp = 0x81・格納仮数 0。
- 単精度 `[m0][m1][m2][exp]`: bits = m0 | m1<<8 | (m2 & 0x7F)<<16 | 0x800000、
  値 = 符号 × bits × 2^(exp−152) = 符号 × (1 + frac/2^23) × 2^(exp−129)
- 倍精度 `[m0..m6][exp]`: bits = 55 ビットの frac | 1<<55、
  値 = 符号 × bits × 2^(exp−184)
- 0x0B は 8 進で出力する（値 15 → `&O17`）。

### 変換後の定数の書き方（型と値を保つ）

変換後のテキストはインタプリタが読み直す。インタプリタの定数パーサ
（src/num.c `str_to_num`）は**書き方から型を決める**:

| 書き方 | 読まれる型 |
|---|---|
| 接尾辞 `%` / `!` / `#` | 整数 / 単精度 / 倍精度 |
| 指数文字 `D` | 倍精度 |
| 指数文字 `E` | 単精度 |
| 小数点なし・値 32767 以下 | 整数 |
| 桁数（先行ゼロを除く数字の個数）が 8 以上 | 倍精度 |
| それ以外 | 単精度 |

単精度として読まれた定数が 1.70141E+38 を超えると Overflow になる。

変換器（src/p88conv.c `put_num_literal` / tools/p88_detok.py
`num_literal`）は、数字列を Python の `repr()` と同じ「読み直すと同じ
binary64 になる最短の 10 進」にし（C 側も同じ数字列・同じ指数形式を
出す）、文字と接尾辞を次のように選ぶ:

| トークン | 値の範囲 | 出力 | 例 |
|---|---|---|---|
| 単精度 | 1e-4 ≤ 値 < 1e16、7 桁以下 | そのまま | `1.0` `0.5` |
| 単精度 | 同、8 桁以上 | `!` を付ける | `16777216.0!` `0.10000000149011612!` |
| 単精度 | 指数形式になる値 | 指数文字 `E` | `5.960464477539063E-08` |
| 単精度 | 1.70141E+38 超 | `(半分*2)` | `(8.5070586659632215E+37*2)` |
| 倍精度 | 1e-4 ≤ 値 < 1e16、8 桁以上 | そのまま | `16777216.0` |
| 倍精度 | 同、7 桁以下 | `#` を付ける | `1.0#` `0.5#` |
| 倍精度 | 指数形式になる値 | 指数文字 `D` | `1D-05` |
| 単精度 / 倍精度 | 0 | `0!` / `0#` | |
| int16（0x1C） | 負 | 括弧付き | `(-5)`、−32768 は `(-32767-1)` |

- 負の定数は括弧で囲む（`(-2.5)`）。インタプリタの単項マイナスは `^`
  より弱いので、括弧なしの `-2.5^2` は −6.25 になる。トークン上は
  符号付きの 1 個のオペランド（+6.25）。
- 1.70141E+38 を超える単精度（MBF 単精度の最大値付近）は定数として
  書けないので、半分の値の単精度定数と 2 の積にする。単精度同士の
  乗算は結果が無限大のときだけ Overflow になり（src/eval.c）、積は
  正確にその値の単精度になる。
- 検証: tools/p88conv_test.py が変換結果をホストインタプリタで実行
  し、型と値に依存する計算結果（単精度 16777216 の `(x+1)-x` が 0、
  `(-2.5)^2` が 6.25 など）を確認する。

### 表現上の限界（インタプリタの内部型に合わせた結果）

- **MBF 倍精度 → binary64 の丸め**: MBF 倍精度の仮数は 56 ビット、
  インタプリタの倍精度は IEEE binary64（仮数 53 ビット）。変換時に
  仮数を 53 ビットへ丸める（最近接・偶数丸め）ので、下位 3 ビットを
  使う定数は元の値と一致しない。例: ペイロード
  `01 00 00 00 00 00 00 81`（1 + 2^-55）は `1.0#` になる。インタプリタ
  自身がこの値を保持できないため、変換器側では直さない（直せない）。
- **ごく小さい MBF 単精度**: インタプリタの単精度は IEEE binary32。
  指数バイトが 1 または 2 の MBF 単精度（絶対値 2^-126 未満）は
  binary32 では非正規化数になり、仮数の下位 1〜2 ビットが読み直し時に
  丸められることがある。

## キーワード（1 バイト、抜粋ではなく実測で埋まった分）

GW-BASIC の並びが土台で、PC-88 拡張が C0–FE に入る。

- 0x81 END / 0x82 FOR / 0x83 NEXT / 0x84 DATA / 0x85 INPUT / 0x86 DIM /
  0x87 READ / 0x88 LET / 0x89 GOTO / 0x8A RUN / 0x8B IF / 0x8C RESTORE /
  0x8D GOSUB / 0x8E RETURN / 0x90 STOP / 0x91 PRINT / 0x92 CLEAR /
  0x95 ON / 0x97 DEF / 0x98 POKE / 0x9A OUT / 0x9D CONSOLE / 0x9E WIDTH /
  0x9F ELSE / 0xAB DEFSNG
- 0x8F 0xE9 = アポストロフィコメント（行末まで素テキスト）
- 0xAE LINE / 0xAF WHILE / 0xB0 WEND
- 0xCB COLOR（`COLOR 7,0` 形式と `COLOR=(n,c)` パレット形式の両方） /
  0xCE CLS（引数付きあり） / 0xD3 SCREEN / 0xD4 BLOAD / 0xD6 LOCATE /
  0xDC TO / 0xDD THEN

## 関数（0xFF + 1 バイト）

| コード | 意味 | 根拠 |
|---|---|---|
| FF82 | RIGHT$ | `RIGHT$("  "+STR$(I),3)` の形で番号を右詰め表示。FF83 = MID$ の確定により LEFT$/RIGHT$/MID$ の並びで確定 |
| FF83 | MID$ | FC88V42 MENU.ALP 286 行 `TM=VAL(<FF83>(<FFDC>,8,1))` と、460 行に残る素テキスト `'PM=VAL(MID$(TIME$,1,2))` の対応 |
| FFDC | TIME$ | 同上（"HH:MM:SS" の秒 1 の位を取り出す） |
| FF90 | INP | キーボードマトリクス（0–10）とポート読みに使用 |
| FF92 | LEN | タイトル右寄せ計算 `79-LEN(A$)` |
| FF93 | STR$ | 数値を文字列化して連結 |
| FF94 | VAL | `VAL("&h"+PT$)` |
| FF97 | PEEK | &HFFF8 等の状態バイト、曲テーブル &HC800 読み |
| FF9A | HEX$ | 数値→16 進文字列（VAL と対で使用） |
| FF85 | INT（推定） | 中央寄せ計算 `(80-LEN(A$)*X)/2` の結果 |

## ラベル

- 定義: 行頭に `*名前`（素の ASCII）。例: `*STP` `*BGMP` `*SELECT` `*STAFF`
- 参照: GOTO / GOSUB / RESTORE の引数に `*名前`（0xF5 + 名前で格納）
- 変換器（src/p88conv.c / tools/p88_to_bas.py）はラベルを行番号へ
  下ろさず `*名前` のまま出力し、インタプリタ本体のラベル対応
  （上流 Ver.261119、token.c / exec.c）が解決する。プログラム内に
  定義の無いラベル参照（MENU.ALP 284 行の `*TYPE`）もそのまま通し、
  変換レポートに `UNDEFINED label` を出す。実行された場合は実機と
  同じく未定義エラー（「その行番号はありません」）になる。
- ラベル名の読み方と照合はインタプリタの文法に合わせる（解決するのは
  インタプリタなので）:
  - 名前は英字で始まり、英数字と `.` が続く（token.c のラベル走査、
    exec.c `label_char`）。`*100` はラベルではない（`GOTO *100` は
    Syntax error）。数字始まりの「定義」は定義として数えず、数字
    始まりの参照には `UNDEFINED label` を出す。
  - 大文字小文字は区別しない（トークナイザが定義も参照も大文字に
    する）。`GOTO *a` は `*A` に届き、警告は出ない。
  - 定義は行の最初にある `*名前`（前の空白は可）。名前全体が一致した
    ときだけ見つかる（`*SUB` は `*SUB.1` に一致しない）。同名の定義が
    複数あれば最初の行。
  - 警告 `UNDEFINED label` は、インタプリタがその参照を解決できない
    ときにだけ出る。
- ラベルの直後にキーワードのトークンが続く場合、そのまま並べると
  インタプリタのトークナイザがキーワードまでラベル名として読む
  （`*ABC` + PRINT → ラベル `ABCPRINT`、文が消える）。変換器は区切りを
  補う: 定義の直後なら `:`（`*ABC:PRINT "X"`、MA2026 自身の
  `*名前:文` と同じ形）、参照の直後なら空白（`THEN *A ELSE *B`）。
  すでに `:` や空白が続いている定義・参照の出力は変えない。

## 拡張命令（NEOMSC ドライバ提供とみられる 3 命令）

いずれも 0xFF + 1 バイトの文トークン。名前は不明のためコードで呼ぶ。
引数の形だけ実測で分かっている。意味の確定は実装時の課題。

| コード | 引数の形（実測） | 推定される役割 |
|---|---|---|
| FFDD | 先頭が機能番号のことが多い: (9,addr) (8,addr) (6,1,1,24,140,"題") (5,3,1,41,6; A-1,0) (7,3,0,x,y; A-1,3) (1,3,1,x,y; A-1,3) (4,3,0,74,17,"ended ") / 例外 (C,T,B,X,Y,A$) | 画面パターン・文字表示系サービス。MENU 162 行の (C,T,B,X,Y,A$) は曲情報の登録か |
| FFDE | (0,drv,trk,sec,cnt,addr) (1,0,ST,RT) (2,addr,len,addr) / 機能 3 系: (3,10) (3,11,n) (3,9,addr) (3,8) (3,col,文字列) | ディスク直接読み（旧コードのコメントでは RBYTE 相当）と、機能 3 = スタッフロール文字表示 |
| FFDF | 1–2 文字のコマンド名 + 任意引数: S / P / F,速度 / E,12 / E,15 / ES,0 / R,addr / K,addr | 音楽ドライバ制御。P=再生、S=停止、F=フェードアウトは文脈からほぼ確実 |

## MA2026 プログラムの構造（読み解けた全体像）

- 起動は MENU.ALP: メモリ初期化（CLEAR ,&H97FF）、画面初期化、
  `BLOAD "NEOMSC",R` で Z80 ドライバを読み込み実行。
- サウンドボード判定: OUT/INP で SB2（YM2608）を探し、無ければ
  YM2203 モード（SB=1）。結果は POKE で &HFFFD に &HB1/&HB2 を書く。
- PMD データ読み: FFDE で予約領域から直接セクタ読み
  （&HAA00 へ PMD 本体相当、&HCA00 へ MML オブジェクト、&H5500 へ PCM）。
  旧方式（BLOAD "pmd" / RBYTE）はコメントアウトされて残っている。
- 曲テーブルは &HC800 に 4 バイト/曲（トラック、セクタ、セクタ数、予備）。
  MENU.ALP が DATA 文から組み立て、menu と共有する。
- menu が UI 本体: 曲リスト表示（LOCATE/PRINT）、キーボードマトリクス
  （INP(0..10)）による選択・再生操作、FFDF でドライバ制御、
  スタッフロール（RESTORE *STAFF + FFDE 機能 3）。
- 状態共有はメモリ直書き: &HFFF8 = 次に再生する曲、&HFFF9 = 現在の曲、
  &HFFFC/&HFFFD = ドライバモード、&HAA20/&HAA21 = PMD 再生状態。
- 画面はテキスト VRAM 直書き（TXR=&HF418、1 行 120 バイト計算）や
  LINE によるグラフィック描画（タイトル帯）を併用する。
